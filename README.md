# Дүкен Касса + Supabase: запуск за 20 минут

В папке:

| Файл | Что это |
|---|---|
| `index.html`, `app.js` | сама касса (сайт) |
| `config.js` | адрес вашей базы — **заполнить** |
| `supabase/schema.sql` | таблицы, права доступа и серверные операции — **выполнить в Supabase** |

---

## 1. Создайте проект Supabase

1. Зайдите на https://supabase.com → **Sign in** → **New project**.
2. Название — любое (например `duken`), придумайте пароль базы и сохраните его.
3. **Region** — ближайший к Казахстану: *Central EU (Frankfurt)*.
4. Подождите 1–2 минуты, пока проект создаётся.

## 2. Создайте таблицы

1. Слева **SQL Editor** → **New query**.
2. Откройте файл `supabase/schema.sql`, скопируйте всё содержимое, вставьте и нажмите **Run**.
3. Должно появиться *Success. No rows returned*.

Скрипт можно запускать повторно — данные не удалятся.

## 3. Закройте свободную регистрацию

Иначе кто угодно сможет завести себе аккаунт кассира.

**Authentication → Sign In / Providers** (в старом интерфейсе **Providers → Email**) → выключите **Allow new users to sign up** → **Save**.

## 4. Заведите сотрудников

**Authentication → Users → Add user → Create new user**
- Email и пароль сотрудника.
- Галочка **Auto Confirm User** — включена.

**Первый созданный пользователь автоматически становится владельцем.** Поэтому сначала создайте себя, потом кассиров. Каждый потом сможет поменять имя «для чека», нажав на своё имя в правом верхнем углу кассы.

Сделать кассира владельцем (SQL Editor):
```sql
update profiles set role = 'owner'
where id = (select id from auth.users where email = 'почта@пример.kz');
```

| | Владелец | Кассир |
|---|---|---|
| Продажа, скан, оплата | ✓ | ✓ |
| Новые товары, правка цен | ✓ | ✓ |
| Приход по накладной | ✓ | ✓ |
| Возврат | любого чека | только своего |
| Отчёт «Продажи» | весь магазин, с прибылью | только свои чеки |
| Списание, инвентаризация, удаление товара | ✓ | — |

## 5. Впишите ключи в `config.js`

**Project Settings → API** (или кнопка **Connect** вверху):
- **Project URL** → в `url`
- ключ **anon public** (или **publishable**) → в `anonKey`

```js
window.DUKEN_CONFIG = {
  url: 'https://abcdefgh.supabase.co',
  anonKey: 'eyJhbGciOi...',
  shopName: 'Дүкен',
  shopSubtitle: 'Продуктовый магазин',
};
```

⚠️ Ключ **service_role / secret** сюда **никогда** не вставляйте — он даёт полный доступ к базе.

## 6. Выложите сайт

**Вариант А — Netlify, без регистрации кода (проще всего)**
1. Откройте https://app.netlify.com/drop и войдите.
2. Перетащите **всю папку** `duken-supabase` в окно.
3. Через минуту получите адрес вида `https://....netlify.app`. В **Site configuration → Change site name** можно сделать `duken-kassa.netlify.app`.
4. Чтобы обновить сайт — снова перетащите папку в **Deploys** этого сайта.

**Вариант Б — Vercel**
1. https://vercel.com → **Add New → Project**.
2. Загрузите папку в GitHub-репозиторий и импортируйте его, либо через терминал: `npx vercel` в этой папке.
3. Framework preset — **Other**, настройки сборки не нужны.

## 7. Кассовый компьютер

- Откройте адрес сайта в Chrome, войдите. Вход запоминается.
- Chrome → меню ⋮ → **Сохранить и поделиться → Установить страницу как приложение** — касса откроется отдельным окном с ярлыком на рабочем столе.
- **Сканер штрихкода**: USB-режим «клавиатура» (HID) с Enter после кода — так настроено почти у всех сканеров с завода. Сканировать можно на любой вкладке, кликать в поле не нужно.
- **Весы с печатью этикеток**: штрихкод вида `2X PPPPP WWWWW C` — программа достанет PLU и вес. У весового товара в карточке укажите тот же PLU, что на весах.
- Горячие клавиши: **F2** — к поиску, **F9** — оплата, **Esc** — закрыть окно.

## Как это устроено

- Продажа, возврат, приход, списание и инвентаризация выполняются **на сервере** одной операцией: либо целиком, либо никак. Две кассы одновременно не собьют остаток. Цена берётся из базы, а не из браузера.
- Остаток нельзя поменять вручную — только через операции склада, каждая попадает в историю.
- Товар «удаляется» в архив: история продаж по нему сохраняется.
- Остатки на всех кассах обновляются сразу (Realtime). Если живое обновление недоступно, каталог перечитывается каждые 5 минут.
- Номера чеков сквозные: 000001, 000002…

## Ограничения прототипа

- **Не фискальная касса.** Чек не передаётся в ОФД. Для законной работы в РК нужна онлайн-ККМ или интеграция с фискальным сервисом — это следующий этап.
- Kaspi QR и терминал отмечаются вручную, без интеграции.
- Без интернета продажа не проводится (корзина сохраняется, пока связь не вернётся).
- Бесплатный тариф Supabase: 500 МБ базы (хватит на сотни тысяч чеков); проект **засыпает после 7 дней без активности** — при ежедневной работе кассы это не случится. Для надёжности позже стоит перейти на платный тариф (есть ежедневные бэкапы).

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| «Касса ещё не подключена к базе» | не заполнен `config.js` |
| «Неверный email или пароль» | проверьте пользователя в Authentication → Users, включён ли Auto Confirm |
| «Для этой учётной записи нет профиля» | запустите `schema.sql` ещё раз |
| «Недостаточно прав» | действие доступно только владельцу |
| «Нет связи с сервером» | проверьте интернет; в Supabase проект не должен быть на паузе |
